## 1. Motivation: The Silent Failure Story That Demands Per-Agent Epistemics

Suppose a scheduled job runs an experiment on a remote B200 GPU host (`newtonne-b200`) and exits non-zero:

```text
exit_code = 1
stderr    = "ssh: connect to host newtonne-b200 port 22: Connection timed out"
```

A downstream summarizer sees `exit_code = 1`, jumps to *"hypothesis refuted"*, and closes the shared tracker issue. Without an explicit record separating **raw environment observations** from **each agent's reasoning chain and justification**, bad conclusions propagate directly into task queues—and two agents end up claiming or closing the same task for contradictory reasons.

<Callout type="note" title="Quick Concept Glossary">
  <p><strong>WorldState</strong>: Immutable observed fact snapshot (e.g., <code>WorldState_ws_ubuntu_run</code>) tagged with a timestamp and SHA-256 content hash.</p>
  <p><strong>BDI Chain (Belief → Desire → Intention)</strong>: Each agent (<code>codex</code>, <code>claude</code>, <code>antigravity</code>) writes persistent Beliefs grounded in a <code>WorldState</code> and <code>Justification</code>, linked to role-specific Desires and committed Intentions inside its own named RDF graph.</p>
  <p><strong>SPARQL Integrity Gates (<code>V1–V5</code> &amp; <code>Q_CONFLICT</code>)</strong>: Deterministic queries executed before any <code>bd</code> write—rejecting unjustified beliefs, stale file hashes, cross-agent polarity contradictions, or double-claimed execution tasks.</p>
  <p><strong>Beads (<code>bd</code>)</strong>: Git-adjacent Dolt issue tracker holding epics, <code>blocks</code> DAG dependencies, and atomic <code>--claim</code> task ownership.</p>
</Callout>

## 2. Architecture: Per-Agent Named Graphs Bridging Observations to Beads

## 5. How Design Choices Shaped Real Outcomes (and Extending to Coding Agents)

Running live agents surfaced two architectural boundaries immediately. First, `target_issue_id` (an epistemic audit reference) must stay distinct from `plan_tasks` (an execution claim): when both reviewer (`claude`) and worker (`codex`) populated execution components on `synexp-th0.1`, SPARQL flagged healthy consensus blocking as a duplicate-claim collision. Second, shared `WorldState` ingestion must preserve custom external telemetry triples when re-scanning Beads issues, or downstream `V2` integrity gates rightfully freeze mutations.

**Extending cleanly to Coding Collaboration Agents**: Because each `.ttl` graph already enforces `WorldState` SHA-256 pinning (`V5`), cross-agent `Q_CONFLICT`, and task claim separation (`Q_DOUBLE_CLAIM`), extending this to multi-agent software engineering requires adding only two lightweight mappings without changing the core engine:
- **File / Symbol Scope as `WorldState`**: Ground coding beliefs in exact file SHA-256 + symbol range instead of free prose—if Agent B edits `auth.py`, Agent A's uncommitted patch plan automatically triggers `V5_stale_world_hash`.
- **Reviewer vs Implementer Separation**: Coder agents attach `plan_tasks` for module ownership while reviewer agents attach `target_issue_id` + test output hashes, blocking Beads closure whenever a test-gate refutes the implementation claim.

## 6. Scope Limits & Honest Verification Boundary

- **Sample scale**: Trial 1 ran 12 self-authored gate cases and Trial 2–3 ran one complete live sandbox pass (`codex`, `claude`, `antigravity`); multi-run variance and noisy production concurrency remain untested.
- **Claim-key alignment assumption**: `Q_CONFLICT` detects contradictions cleanly only when agents address the same canonical `WorldState` URI and `claimKey`; unnormalized synonyms bypass syntactic conflict matching.
- **Next step**: Validate `V5_stale_world_hash` auto-invalidation across multi-day cron runs and real two-agent coding PR workflows.
