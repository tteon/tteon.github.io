## 1. Motivation: Why Static Ontology Injection Backfires

When Text2SQL or Text2Cypher pipelines return wrong numbers, teams reflexively append full domain ontologies, type hierarchies, and column rules into the system prompt. On paper this removes ambiguity; in practice, stuffing 1,400–1,600 extra tokens of schema rules into every request alters query generation differently depending on question topology.

## 2. Tier Definitions & Real Paired Examples (`cq_dataset.jsonl`)

Stage A evaluated four conditions (`neo-no-onto`, `neo-onto`, `pg-no-onto`, `pg-onto`) across 5 query tiers (80 paired requests per tier; 1,600 total). Here is what each tier tests and what flipped in actual `records.jsonl` runs:

- **Tier 1 (Direct 1-hop entity lookup)**: *"Who sits on TSMC's board of directors?"*
- **Tier 2 (Computed ratio / derived metric — Biggest Ontology Win)**: *"What was Albemarle's return on equity in fiscal year 2024?"* (`cq2_085`)
  - Without ontology (`pg-no-onto` → **empty**): guessed a literal row `WHERE md.name ILIKE '%return on equity%'` that does not exist in `metric_definitions`.
  - With ontology (`pg-onto` → **correct**): knew ROE is computed from `net_income` ÷ `stockholders_equity` and synthesized joined `CTE`s over `metric_code = 'net_income'`.
- **Tier 3 (Multi-condition similarity / attribute filter — Ontology Regression)**: *"Which other companies disclose risk factors in the 'Operations and manufacturing' risk category, as TSMC does?"* (`cq3_133`)
  - Without ontology (`pg-no-onto` → **correct**): resolved `WHERE ticker = 'TSM'` cleanly.
  - With ontology (`pg-onto` → **empty**): emitted `WHERE name ILIKE '%TSMC%'` (missing rows stored under full legal name `Taiwan Semiconductor...`) and extra column constraints, dropping matched rows to zero.
- **Tier 4 (Multi-hop / supply-chain traversal)**: *"As of 2026-06-30, which companies within two supply tiers upstream of SpaceX did Renaissance Technologies hold?"* (`cq4_163`)
  - With ontology (`pg-onto` → **syntax error**): synthesized self-referencing CTE `WITH upstream AS (... FROM upstream up ...)` omitting `WITH RECURSIVE`, triggering PostgreSQL `UndefinedTableError`.
- **Tier 5 (Unanswerable abstention)**: *"Give Caterpillar's most recent number of patents granted."* (Expected: decline).

## 5. Mechanism Breakdown: Why Aggregate Accuracy Masks Two Opposite Regimes

1. **Ontology fixes missing derived formulas via curated attributes (Tier 2)**: Without derived metric definitions (`net_income` / `stockholders_equity`), the LLM invents nonexistent metric names (`wrong` answers drop from 28 to 1 on Postgres, 18 to 6 on Neo4j). Crucially, `FINDINGS.md §2` notes Auto-Ontology's automatic layer compiled **0 SQL attributes** from row-stored metrics (`metric_definitions × financial_metrics`)—the `42` human-curated SQL attributes drove the Tier 2 jump.
2. **Aggregate +0.070 hides Tier 3 template/grounding drift and Tier 4 recursion bugs**: Tier 3 did *not* break because of syntax errors (only 1 syntax error in Tier 3). Auditing `31` Postgres regressions revealed two concrete causes: matched concept-level query templates induced per-row rather than distinct outputs, and the extra context shifted entity linking away from canonical tickers (`152 → 105` queries) toward loose name filters like `ILIKE '%TSMC%'`. Syntax errors happened in **Tier 4**, where abstract path semantics pushed self-referencing CTEs without `WITH RECURSIVE`. Meanwhile, Text2Cypher trailed Text2SQL by `0.17` across both arms due to exact property lookups `{name: '...'}` (`122–146` of `~320` queries/arm at `~0%` accuracy vs `0.45–0.67` when ticker-anchored).
3. **LLM inference, not local Postgres latency, dominates E2E cost**: Local Postgres DB time remained under `0.05%` of E2E latency (`1.1 → 2.6` ms vs `5,697 → 7,836` ms LLM); doubling prompt size added `~2.2–2.7` seconds to median LLM inference, plus `54` s median on `check_answerable`.

## 6. Key Findings & Transferable Insights

*Distilled via multi-agent deliberation (`Codex` systems practitioner + `Claude` evidence gate) from `FINDINGS.md` §1–§2:*

- **Curate row-stored metrics explicitly; automatic schema ingestion misses semantic metrics**: Auto-Ontology compiled `0` SQL attributes from `metric_definitions` rows, whereas `42` curated attributes drove `+0.725`. **Rule:** Inspect compiled attribute yield directly instead of trusting `schema ingested = covered`.
- **Do not run uncalibrated `check_answerable` inline on concurrent paths**: `_run_lock` serialized `check_answerable` at `~1 call/53 s` (`79/80` timed out past `180 s` at `c=8`), and answerable Tier 2 questions scored only `0.20–0.33` coverage—forcing dev calibration to choose **no abstention gate**.
- **Assert non-empty context (`ctx_chars`, `ctx_matched_sql`) in request telemetry**: Candidate IDs turned out to be *attribute IDs*, not term IDs—causing silent 404s that passed empty ontology contexts (`*-buggy` runs), while incompatible `lightning-30b` threw HTTP 400 × 3 (`~89 s`) before silently falling back to the raw prompt.
- **Anchor entities canonically before query generation & restrict ingested catalog views**: Ticker-anchored Cypher (`0.45–0.67`) massively beat ungrounded exact `{name: ...}` matches (`~0%`), and naive `pg_catalog` introspection ingested internal monitoring views like `pg_stat_statements`.

## 7. Scope Limits & Next Experiment

- **Dependent repeats & review status**: The `80` pairs/tier represent `40` questions × `2` temperature-0 repeats, all `250` gold items remain `pending-human-review`, and Tier 2 curation itself can favor the ontology arm (`FINDINGS.md §6`). Stage B Aura DB throughput sweeps are withheld behind Neo4j AUP (`yw-pow.6`).
- **Next step**: Test **tier-gated selective ontology injection**—supply curated metric definitions only on computed signatures, resolve canonical ticker/entity IDs deterministically before filter generation, and supply explicit `WITH RECURSIVE` templates for Tier 4 path queries.
