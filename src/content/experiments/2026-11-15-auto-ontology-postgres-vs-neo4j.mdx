## 1. Motivation: Why Static Ontology Injection Backfires

When Text2SQL or Text2Cypher pipelines return wrong numbers, teams reflexively append full domain ontologies, type hierarchies, and column rules into the system prompt. On paper this removes ambiguity; in practice, stuffing 1,400–1,600 extra tokens of schema rules into every request alters query generation differently depending on question topology.

## 2. Tier Definitions & Real Paired Examples (`cq_dataset.jsonl`)

Stage A evaluated four conditions (`neo-no-onto`, `neo-onto`, `pg-no-onto`, `pg-onto`) across 5 query tiers (80 paired requests per tier; 1,600 total). Here is what each tier tests and what flipped in actual `records.jsonl` runs:

- **Tier 1 (Direct 1-hop entity lookup)**: *"Who sits on TSMC's board of directors?"*
- **Tier 2 (Computed ratio / derived metric — Biggest Ontology Win)**: *"What was Albemarle's return on equity in fiscal year 2024?"* (`cq2_085`)
  - Without ontology (`pg-no-onto` → **empty**): guessed a literal row `WHERE md.name ILIKE '%return on equity%'` that does not exist in `metric_definitions`.
  - With ontology (`pg-onto` → **correct**): knew ROE is computed from `net_income` ÷ `stockholders_equity` and synthesized joined `CTE`s over `metric_code = 'net_income'`.
- **Tier 3 (Multi-condition similarity / attribute filter — Ontology Regression)**: *"Which other companies disclose risk factors in the 'Operations and manufacturing' risk category, as TSMC does?"* (`cq3_133`)
  - Without ontology (`pg-no-onto` → **correct**): resolved `WHERE ticker = 'TSM'` cleanly.
  - With ontology (`pg-onto` → **empty**): emitted `WHERE name ILIKE '%TSMC%'` (missing rows stored under full legal name `Taiwan Semiconductor...`) and extra column constraints, dropping matched rows to zero.
- **Tier 4 (Multi-hop / supply-chain traversal)**: *"As of 2026-06-30, which companies within two supply tiers upstream of SpaceX did Renaissance Technologies hold?"* (`cq4_163`)
  - With ontology (`pg-onto` → **syntax error**): synthesized self-referencing CTE `WITH upstream AS (... FROM upstream up ...)` omitting `WITH RECURSIVE`, triggering PostgreSQL `UndefinedTableError`.
- **Tier 5 (Unanswerable abstention)**: *"Give Caterpillar's most recent number of patents granted."* (Expected: decline).

## 3. Environment & Statistical Protocol

Both conditions ran paired evaluation on identical question repeats (`n=80` pairs/tier), scoring lenient gold-set match on Tiers 1–4 and correct abstention on Tier 5. Significance uses two-sided paired McNemar tests; bracketed ranges denote 95% bootstrap confidence intervals. Stage B separately replayed DB-only queries across concurrency 1–256 (`stageB-real`).

## 5. Mechanism Breakdown: Why Aggregate Accuracy Masks Two Opposite Regimes

1. **Ontology fixes missing derived formulas (Tier 2)**: Without derived metric definitions (`net_income` / `stockholders_equity`), the LLM invents nonexistent metric names (`wrong` answers drop from 28 to 1 on Postgres, 18 to 6 on Neo4j).
2. **Aggregate +0.070 hides Tier 3 over-filtering and Tier 4 recursion bugs**: Tier 3 did *not* break because of syntax errors (only 1 syntax error in Tier 3). Instead, extra entity/relationship rules caused overly strict joins and name matching (`empty` grew 41 → 50, `wrong` grew 0 → 8). Syntax errors happened almost exclusively in **Tier 4**, where prompting abstract path semantics pushed the model to write self-referencing CTEs without `WITH RECURSIVE`.
3. **LLM inference, not DB speed, dominates latency**: DB wall time accounts for under 0.05% of Postgres end-to-end latency (2.6 ms vs 7,836 ms LLM) and ~1.2% on Neo4j (119.1 ms vs 10,153 ms). Even so, doubling prompt size added ~2.2–2.8 seconds to median response latency.

## 6. Scope Limits & Next Experiment

- Results depend on this benchmark's financial ontology schema and the model tested in Stage A; other query-repair loops or recursive SQL few-shots could reduce the Tier 4 syntax jump (`12 → 39`).
- **Next step**: Test **tier-gated selective ontology injection**—supply derived metric definitions only on metric/aggregation signatures, enforce canonical ticker/ID linking rules for multi-condition filters, and include explicit `WITH RECURSIVE` templates on Tier 4 path queries.
