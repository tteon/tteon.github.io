## 1. Motivation: The Half-Life of Cloud GPU Benchmarks

Most multi-agent database benchmarks run on ephemeral GPU instances (such as Vast.ai). Once the VM is destroyed, readers cannot re-run live inference—so numbers in blog posts quickly become unverifiable trust-me claims. Even worse, authors sometimes mix offline artifact checks with claims about live generalization.

## 3. Environment & Replay Commands

This audit ran offline against preserved artifacts (`sr-9jb6`) with zero remote VM mutations, writing re-derived outputs exclusively to isolated `/tmp` folders:

```bash
python3 -m unittest discover -s experiments/vast_finbench_validation -p 'test_*.py' -v
python3 -m unittest discover -s experiments/vast_finbench_probes -p 'test_*.py' -v
python3 -m unittest discover -s experiments/vast_finbench_db_replay -p 'test_*.py' -v
python3 -m unittest discover -s docs/blog/text2cypher-bottlenecks -p 'test_*.py' -v
python3 docs/blog/text2cypher-bottlenecks/verify_package.py
```

## 5. Mechanism Breakdown: Why Separating Replay Integrity From Live Scope Matters

Notice the deliberate verdict choice: **our offline reproducibility hypothesis is Supported** (56/56 tests, 713/713 manifests, 4/4 JSON outputs match identically). However, in an earlier draft we labeled this *Mixed* by conflating offline checksum proof with live inference generalizability. Keeping the verdict clean (`Supported` for archive reproducibility) while highlighting the exact historical bounds in Figure 1 (13 baseline queries with 8/13 original pass and 7/13 strict contract; 3 probe questions × 7 conditions × 1 trial; 180 DB replay runs; 30 query pairs (60 paired runs)) preserves clarity without softening boundaries.

Additionally, inspecting `tteon/gare2e@07d7453c` verified provenance: `gare2e` branched directly from `tteon/seocho` commit `c3a1871` via `5422522`, explaining why SEOCHO packaging metadata appears in `gare2e` root manifests.

## 6. Scope Limits & Next Experiment

- **Not a live statistical proof**: SHA-256 identity proves zero post-capture tampering, not that page-cache misses dominate CPU/I/O/lock stalls or that interface deltas hold across unseen question sets.
- **Mock paths in unit checks**: Part of the 56 unit checks stub external DB/LLM drivers cleanly rather than hitting live Neo4j or vLLM processes.
- **Next step**: Re-run page-cache vs CPU/I/O lock isolation profiling on dedicated local hardware when attribution experiments resume.
