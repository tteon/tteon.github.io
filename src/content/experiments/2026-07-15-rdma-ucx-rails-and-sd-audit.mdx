## 1. Motivation: The Gap Between Theoretical Bandwidth, Speculative Speedup, and Real Systems

High-level benchmarks break down in production for mundane systems reasons: an uncalibrated transport flag caps a 400 Gbps fabric to a single NIC lane (`13.1 GB/s`), an unverified speculative decoder subtly shifts sampling probabilities, or an API model passes a 10-minute smoke test before degrading across multi-day traffic windows. Here we bundle three concrete engineering audits across our transport (`obsidian/260414`), kernel (`mlsys/graphkv-cosched`), and contract (`mara`) labs—strictly separating measured facts from unrun analytical baselines.

## 2. Hypothesis, Falsification & Experimental Mechanism

We hypothesized (`Mixed` across the three low-level stacks) that transport defaults, speculative kernel verifiers, and multi-day API drift harbor silent cliffs undetectable in short smoke runs; falsified if default multi-rail flags saturated 400 Gbps, SD observer tracing exceeded 5% overhead, or single-day API checks held steady across 3 days.

## 5. Mechanism Breakdown: Subtle Bugs Caught Only by Micro-Audits

1. **Why UCX Multi-Rail silently drops half your NICs**: On Linux RoCEv2, engineers routinely verify NIC bonding with `ib_write_bw` or `ucx_perftest` (`tag_bw = 217 Gbps` = `27.1 GB/s`) after setting `UCX_MAX_RNDV_RAILS=4`. However, NIXL transfers invoke UCX's **RMA (`ucp_put_nbx`)** transport, which reads `UCX_MAX_RMA_RAILS` (default `1`)—silently throttling 4-rail hardware to `13.10 GB/s`. Additionally, `proto_multi_filter` drops cross-NUMA NICs on single-GPU ranks (`~111 Gbps` vs `~200 Gbps` on TP=2), and registering `1,024 × 1 KB` descriptors separately triggers `~53.8 ms` `ibv_reg_mr()` + `~116.9 ms` descriptor allocation (`~171 ms` for `1 MB`!).
2. **Separating SD observer overhead from speculative speedup**: Running SGLang NGRAM over repeated identical synthetic KG schemas warmed the draft corpus abnormally cleanly (`309–340` `correct_drafts`), and prior smoke attempts `...-01..04` crashed on startup/NUMA/VRAM. Therefore `graphkv-sd-trace` validates **only** that async tracing adds `~1.36%` observer tax and kernel sampling matches scalar probability—it does *not* claim production speculative decoding gains on open workloads.

## 6. Key Findings & Transferable Insights

*Distilled via multi-agent deliberation (`Codex` + `Claude`):*

- **Coalesce KV transfers toward `≥16–256 KB` and configure the transport API actually invoked**: `1 KB` and `16 KB` take virtually identical wall time (`12.8 µs` vs `11.9 µs`) because software submission (`~7.5 µs`) dominates—making small batch coalescing an essentially free bandwidth jump (`0.08 → 1.41 GB/s`), while NIXL RMA paths ignore `UCX_MAX_RNDV_RAILS=4` until `UCX_MAX_RMA_RAILS=4` unlocks `13.10 → 24.39 GB/s`.
- **Negative controls validate kernel verifiers (`0.55 vs 1.0`), and multi-window gates expose variance hidden in 1-day smokes**: `12,288/12,288` scalar parity in CUDA `tree_speculative_sampling_target_only` holds credibility because the biased `0.55` control actually failed the check; similarly, MARA APIs passed `100%` in single windows while swinging `1.1s → 12.4s` p95 across 3 days (`DeepSeek-V3.1` dropped to `0.50` valid).
