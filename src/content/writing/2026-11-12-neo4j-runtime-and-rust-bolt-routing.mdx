When Graph Agentic RAG pipelines connect Python LLM agents directly to a single shared Neo4j database under one default runtime, three failures reinforce each other: **domain entity ambiguity**, **Python GIL queue contention over Bolt**, and **runtime mismatch on heavy scans**.

## 1. Federated Graphs Before Prompt Tuning

Identical company names carry different meanings across document domains (financial filings, supply-chain tables, risk disclosures). Cramming every chunk attribute into one shared label schema bloats property tables until `text2cypher` fails repair loops or returns empty rows.

Before partitioning a database, run a lightweight **TF-IDF term-overlap analysis** across document categories. In the Nodes26 reference dataset, **more than 382 companies appeared across two or more domains**—direct quantitative justification for domain-scoped ontologies evaluated via competency questions before routing across federated graphs:

## 3. Query-Shape Runtime Routing (Measured vs Proposed)

Neo4j Community executes exclusively on `Slotted` (row-by-row volcano operators without intra-query parallelism). Enterprise and Aura add `Pipelined` (fused morsel pipelines) and `Parallel` (partitioned worker scans). Incorporating our controlled [Aura runtime benchmark](/experiments/2026-11-14-neo4j-aura-runtime-routing/), the table below explicitly marks **measured Aura behavior** separately from **untested architectural hypotheses**:

| Query Shape | Bottleneck Profile | Route Choice | Evidence Status |
|---|---|---|---|
| Point index lookup (`W1`) / indexed top-k (`W5`) | Network Bolt RTT (~100 ms) dominates 1–2 ms server cost | `Slotted` or `Pipelined` (avoid `Parallel`) | **Measured (Aura)**: `Parallel` 0.95–0.97× (`+2.2 MB` heap overhead) |
| Seeded local 3-hop walk (`W2`) | Low DB hits (~1.8K–2.8K); server work stays 2–6 ms | `Slotted` or `Pipelined` | **Measured (Aura)**: RTT-bound at 103–107 ms (`Parallel` 0.97×) |
| Global aggregation (`W3`) &amp; supernode fan-out (`W6`) | Moderate CPU/memory scan above RTT floor | `Parallel` (low concurrency) | **Measured (Aura)**: 1.17× speedup on single stream |
| Global unanchored 3-hop analytics (`W4`) | Millions of DB hits (6.1M–10.0M) | `Parallel` | **Measured (Aura)**: **4.11×** faster (2,324.6 → 565.4 ms) |
| High-concurrency multi-agent reads (8–64 clients) | Worker thread &amp; heap contention (`Parallel` allocates MBs/query) | Admission cap + `Pipelined` fallback | **Proposed hypothesis**: concurrent worker contention remains untested |

<Callout type="warn" title="Architectural Gap Remaining Open">
Single-stream Aura benchmarks validate why heavy global scans (`W4`) need `Parallel` while shallow local walks (`W2`) stay RTT-bound, but measuring actual Python GIL wait time vs Rust Bolt admission queue throughput under multi-agent concurrency (8–64 parallel callers) requires an isolated load-test harness.
</Callout>
